# Unturned 单人作弊菜单：当前 UI 视觉优化方案

> **文档版本：** 1.0
> **编制日期：** 2026-08-16
> **适用项目：** `UnturnedSingleplayerCheatMenu`
> **文档性质：** 当前界面视觉审计、设计方向、落地规格与验收标准
> **当前结论：** Phase A/B 已按本方案落地。Phase C 的视觉部分已依据用户提供的
> 六页真实运行截图完成验收：普通按钮、输入框、时间滑块、传送点行、生存状态 Toggle、
> 收藏/关闭图标和底部状态栏均已确认有稳定的 Surface 层级、边界和对齐。
> 输入操作、Scale、日志和关闭后的输入恢复等未被明确证明的项目仍单独保留为限制项。

---

## 1. 方案摘要

当前插件已经具备一套可工作的运行时 Overlay UI：使用 Unity uGUI 在
`Screen Space Overlay` Canvas 中动态创建界面，包含角色、物品、车辆、收藏、
传送、其他六个主页面，并已经实现中英文切换、搜索、分页、收藏、空状态、
传送删除确认、时间 Slider、Toggle 和 UI Scale 安全限制等能力。

本方案不建议更换 UI 框架，也不建议引入 AssetBundle、Prefab、第三方 UI
组件库或新的运行时 DLL。推荐的方向是：

> **保留现有 Overlay 架构，把菜单统一为“深色游戏内控制台”风格：**
> 以清晰的信息层级、稳定的状态色、紧凑但有呼吸感的卡片和明确的操作反馈，
> 提升扫描速度与使用确定性，而不是追求装饰性重做。

视觉优化的优先级如下：

1. **先解决层级问题：** 让标题、页面导航、当前上下文、主要操作和反馈状态
   一眼可区分。
2. **再统一组件状态：** Button、Input、Toggle、Slider、Card、空状态和确认框
   使用同一套视觉语义。
3. **最后优化页面密度：** 角色页减少“按钮墙”感，物品/车辆页强化搜索与卡片
   扫描，传送页明确地图状态，其他页按任务分组。
4. **全程保留运行边界：** 不改变单人模式限制、输入捕获、快捷键、资产扫描、
   业务动作和 BepInEx 安全边界。

## 3. 当前 UI 视觉审计

### 3.1 已有优点

#### A. 基础结构清楚

- 顶部标题、单人模式 Badge、地图/快捷键、语言按钮和关闭按钮位置稳定。
- 六个主 Tab 的布局一致，当前 Tab 使用高亮蓝色区分。
- 物品和车辆卡片采用固定网格，适合快速浏览大量资产。
- 分类侧栏、搜索栏和分页结构符合工具型插件的使用习惯。

#### B. 主题方向已经成立

当前深色背景、蓝色主强调色、红色危险操作、金色收藏状态已经形成基本
视觉语言，不需要推翻重做。

#### C. 功能状态覆盖比较完整

当前实现已经考虑了：

- 搜索输入中的即时更新和防抖；
- Toggle 的 ON/OFF 文案；
- 时间 Slider 与精确输入并存；
- 数量上下限；
- 无收藏、无搜索结果、无传送点等空状态；
- 传送点删除确认；
- 状态栏短时反馈；
- UI Scale 超出屏幕时的安全限制。

### 3.2 当前主要视觉问题

以下问题来自当前源码结构与六张界面截图的综合观察。

#### P0：页面层级偏平，主要操作与辅助操作权重接近

角色页、其他页中大量按钮使用相近的深色 Surface，用户需要依赖文字判断
按钮的重要性。对于“开启无敌”“应用生存数值”“呼叫空投”和“重新扫描”
这类操作，缺少明确的 Primary、Secondary、Danger 层级。

**影响：** 扫描速度慢，第一次使用时需要逐个阅读按钮。

**建议：**

- 每个区块最多保留一个 Primary 操作；
- 普通操作使用 Surface；
- 状态切换使用 Accent/Muted 两态；
- 删除、关闭危险天气或不可逆操作使用 Danger；
- 资产卡片的“给予/生成”仍保持整卡可点击，但在 Hover 时增加可操作提示。

#### P1：背景场景参与度略高，降低了文本和控件的稳定对比度

半透明 Panel 能保留游戏氛围，但在树木、天空和高亮游戏 HUD 穿过界面时，
部分辅助文字和空状态文案的可读性会下降。

**建议：**

- 主 Panel 保持深色，但将内容区增加一层非常低透明度的 Surface；
- Header、Content、Status 三个区域使用不同深度，不依赖背景场景来分隔；
- 重要文本至少使用 Text 色，辅助文本使用 Muted 色；
- 不再通过无限加深黑色来解决对比度，避免界面变成一整块黑屏。

#### P1：组件状态没有完全形成统一语义

当前按钮、输入框、Toggle、收藏星标、分页按钮和关闭按钮各自可用，
但状态反馈仍主要依靠颜色变化。对于色觉差异、低亮度场景或快速操作，
仅靠颜色不够。

**建议：**

- Toggle 同时呈现背景色、`ON/OFF` 文案和勾选标记；
- Disabled 同时降低背景、文字和交互能力；
- Favorite 同时使用 `☆/★` 和金色；
- 不可用的分页按钮保留文字但降低对比度；
- 错误和警告状态增加文字前缀，例如“失败：”“提示：”，不要只显示颜色。

#### P1：物品/车辆卡片的元信息密度较高，名称与来源需要更强分层

卡片同时显示图标、名称、ID、GUID/来源和收藏按钮。模组资产名称较长时，
名称可能成为视觉噪声，来源信息又与名称处于相近的水平线上。

**建议：**

- 名称作为唯一主标题，使用 Body/Strong；
- ID 与来源合并为一行 Muted 元信息；
- 来源使用短标签，例如 `原版`、`模组`，避免每张卡片出现过长的来源文字；
- 长名称采用两行截断并保留完整名称的 Hover/点击反馈；
- 收藏按钮始终固定在右上角，并保证不会覆盖图标或标题。

#### P2：角色页和其他页的“按钮墙”感较明显

角色页将生存状态、数值输入、恢复操作、经验、声望和技能操作放在同一
纵向流中；其他页把时间、天气、世界事件和扫描信息连续排列。功能齐全，
但区块之间缺少容器层级。

**建议：**

- 使用“区块标题 + 一行说明 + 操作组”的节奏；
- 重要状态先以 Summary Row 展示，再放修改控件；
- 将高频操作放在首行，低频/危险操作放在下方；
- 允许内容区出现清晰的上下分组，不必给每个小控件增加边框。

#### P2：状态栏是单一的底部黑条，信息语义不足

状态栏已经能传递成功或普通信息，但视觉上与 Panel 过于接近，且不同结果
类型缺少明显差异。

**建议：**

- 保留固定底部 Status Bar，避免引入 Toast 系统；
- 根据状态类型使用左侧色条或小图标：
  - Success：绿色；
  - Info：蓝色；
  - Warning：金色；
  - Error：红色；
- 状态文字保持简短，必要时把对象名称放在后半段；
- 过期后回到“准备就绪”，不要残留旧错误色。

## 4. 推荐视觉方向

### 4.1 设计关键词

**深色、克制、清晰、工具感、游戏内原生感、低干扰。**

不采用玻璃拟态、霓虹渐变、大面积发光、复杂阴影或持续动画。插件的核心
任务是快速执行操作，不是占据视觉焦点。

### 4.2 页面骨架

建议保持现有顶部 Tab 架构，不在当前优化周期强行改成左侧主导航。
推荐的页面骨架如下：

```text
┌─────────────────────────────────────────────────────────────┐
│ 标题      SINGLEPLAYER Badge          地图 · 快捷键  语言  × │
├─────────────────────────────────────────────────────────────┤
│ 角色 │ 物品 │ 车辆 │ 收藏 │ 传送 │ 其他                     │
├─────────────────────────────────────────────────────────────┤
│ 页面标题/上下文                                              │
│ 工具栏：搜索、数量、筛选、主要操作                            │
├───────────────┬─────────────────────────────────────────────┤
│ 分类/过滤侧栏  │ 主内容：状态卡、资产卡、表单或列表            │
├─────────────────────────────────────────────────────────────┤
│ 状态栏：成功 / 提示 / 警告 / 错误                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 推荐设计 Token

以下是对现有 `CheatMenuStyle` 的视觉规格建议。数值不要求一次性全部替换，
优先保证语义一致。

#### 颜色

| Token | 建议值 | 用途 |
|---|---|---|
| `Panel` | `#0B1118` / 96–98% | 主面板 |
| `Surface` | `#151E28` | 普通按钮、卡片、列表行 |
| `SurfaceRaised` | `#1D2936` | Hover、选中容器、弹窗 |
| `SurfaceInput` | `#0D141D` | 输入框和精确数值 |
| `SurfaceInset` | `#121820` | 传送点行、状态栏等低突兀容器 |
| `Accent` | `#168DDD` | 当前 Tab、Primary、开启状态 |
| `AccentBright` | `#43B7FF` | Slider 手柄、焦点边缘、强提示 |
| `Favorite` | `#D5A21E` | 收藏 |
| `Success` | `#4CC38A` | 成功反馈 |
| `Warning` | `#E7B94C` | 警告、跨地图或未完成状态 |
| `Danger` | `#C92F3A` | 关闭、删除和危险操作 |
| `Text` | `#F0F5FA` | 主文本 |
| `Muted` | `#A3B2C2` | 辅助文本 |
| `DisabledText` | `#697787` | 禁用文本 |
| `InputBorder` / `SliderBorder` | 低饱和灰蓝 | 输入框、滑块外框和轨道边界 |
| `StatusBorder` / `TeleportBorder` | 低饱和灰蓝 | 状态栏、传送点列表行边界 |

颜色只表达语义，不把所有控件都染成 Accent。推荐同时检查普通文本与
背景的对比度，尤其是 `Muted` 在半透明背景上的实际表现。

#### 字体

| 角色 | 建议字号 | 建议字重 |
|---|---:|---|
| 页面标题 | 24–26 | Bold |
| 区块标题 | 17–18 | Bold |
| 主按钮/Tab | 14–15 | Bold |
| 正文/卡片名称 | 12–14 | Regular/Bold |
| 辅助元信息 | 10–12 | Regular |
| 状态栏 | 12–13 | Regular |

中文和英文使用相同的视觉角色，不为英文单独扩大所有控件；只在必要位置
增加标题或标签的安全宽度。

#### 间距与尺寸

| Token | 建议值 |
|---|---:|
| 页面边距 | 16–20 |
| 区块间距 | 12–16 |
| 行间距 | 8 |
| 控件高度 | 34–40 |
| Tab 高度 | 40–44 |
| 卡片宽度 | 150–165 |
| 卡片高度 | 150–165 |
| 收藏按钮触达区 | 至少 32×32 |
| 关闭/删除按钮触达区 | 至少 40×36 |

### 4.4 形状、边界和动效

- 继续使用 Unity 原生 Image，不要求引入圆角资源；
- 使用颜色层级和留白代替大量边框；对输入、滑块轨道、传送点行和状态栏等
  容易与背景融合的容器允许使用 1px 原生 `Outline`；
- 卡片和列表行可以保持直角，统一比强行模拟圆角更重要；
- Hover/Pressed 只使用颜色和轻微透明度变化；
- 若增加动效，优先使用 100–160ms 的透明度或缩放过渡；
- 不做持续发光、闪烁、全屏转场或影响游戏操作的动画；
- 未来若支持减弱动效选项，应默认尊重低动效需求。

## 5. 组件级优化规格

### 5.1 Header

**目标：** 让用户知道“我在哪里、当前地图是什么、怎样关闭菜单”。

- 标题固定左对齐；
- `SINGLEPLAYER` Badge 保留，但减小宽度和视觉重量；
- 地图名与快捷键放在同一组，使用 Muted；
- 语言按钮使用普通 Accent，不与关闭按钮抢夺注意力；
- 关闭按钮使用 Danger，但不扩大到占据整个右上角；
- Header 与 Tab 之间增加明确的垂直间距。

### 5.2 Tab

状态规格：

| 状态 | 背景 | 文字 | 说明 |
|---|---|---|---|
| Normal | `Surface` | `Text` | 默认 |
| Hover | `SurfaceRaised` | `Text` | 轻微提升 |
| Active | `Accent` | `Text` | 当前页面 |
| Disabled | `Surface` | `DisabledText` | 不可用 |

Active 不建议再叠加过强描边或闪烁。当前蓝色已经足以表示选中状态。

### 5.3 Button

按钮按语义分级：

1. **Primary：** 应用、保存位置、给予/生成的核心动作；
2. **Secondary：** 白天/夜晚、恢复、重新扫描等普通动作；
3. **Toggle：** 无敌、无限生存、冻结时间、强制满月；
4. **Danger：** 删除、关闭菜单等需要谨慎确认的动作。

每个区块不要出现三个以上同等级 Primary 按钮，否则视觉层级会重新变平。

### 5.4 Input 与 Slider

- 输入框背景与普通 Surface 拉开差异；
- 输入框使用低饱和灰蓝色 1px 边界，Focus 继续使用 AccentBright 焦点条；
- Placeholder 使用 Italic + Muted；
- Focus 时使用 AccentBright 或明显的背景提升；
- 数字输入保持右侧或居中对齐，搜索文本保持左对齐；
- 时间 Slider 的轨道、填充、手柄应形成清晰的三段对比；
- 时间 Slider 控制条不应占据整行高度；当前实现将控件进一步收紧到约 170×22，
  把手约 14×18，并在把手上使用 `///` 纹理模拟实体控制件；
- Slider 的当前值必须同时显示百分比或时间文本，不能只依赖手柄位置。

### 5.5 Toggle

当前运行时 Toggle 继续保留，不需要换成第三方控件。

推荐视觉：

```text
[ ✓  无敌模式   ON ]     [   无限生存状态   OFF ]
```

- ON：Accent 背景 + `✓` + `ON`；
- OFF：Surface 背景 + 空心/弱标记 + `OFF`；
- Disabled：降低背景和文字对比度；
- 点击后即时更新文案和背景，不等待整页重建；
- 不让 Toggle 的颜色成为唯一状态来源。

### 5.6 Asset Card

卡片内容顺序固定为：

1. 图标；
2. 名称；
3. ID/GUID；
4. 来源标签；
5. 右上角收藏。

建议把来源从长句压缩为短标签：

- `原版`
- `地图`
- `模组`

Hover 时可以提升卡片背景并增加轻微图标亮度；Pressed 时降低背景，
让用户知道点击已经被接收。不要改变卡片尺寸，避免网格跳动。

### 5.7 Pagination

- 上一页/下一页保持固定宽度；
- 当前页码居中；
- 不可用时降低对比度，但保留可读文字；
- 在大量资产页显示“当前结果 / 总结果 / 当前页”的组合信息；
- 如果未来支持键盘导航，左右方向键只在焦点位于分页区时生效。

### 5.8 Status Bar

建议为状态文字增加内部类型：

```text
Info     蓝色左条  已重新扫描当前加载的资产。
Success  绿色左条  已给予 3 × 物品。
Warning  金色左条  目标位于其他地图。
Error    红色左条  操作失败：玩家正在载具中。
```

不建议本轮引入复杂消息队列或 Toast 管理器。只需在现有 `SetStatus`
入口上补充轻量类型即可。

### 5.9 Empty State 与 Confirm Dialog

空状态应该回答两个问题：“现在为什么是空的？”和“下一步怎么做？”。

推荐文案结构：

```text
没有已加载的收藏车辆
请在车辆卡片右上角点击 ☆ 收藏。
```

确认框保持轻量：

- 遮罩层；
- 标题；
- 目标名称；
- 取消；
- 删除。

删除按钮继续使用 Danger，取消按钮使用 Secondary，默认焦点应落在取消
或不执行危险操作的一侧。

## 6. 六个页面的具体优化建议

### 6.1 角色页

**当前重点：** 功能完整，但纵向按钮和输入较密集。

建议顺序：

1. 生存状态 Summary Row；
2. 无敌/无限生存两个 Toggle；
3. 指定数值表单；
4. 常用恢复操作；
5. 经验、声望和技能；
6. 低频操作或说明。

视觉上将“当前状态”与“修改状态”分开。生命、饱食、水分、免疫、
体力、氧气可以使用六个紧凑状态值，不必全部做成大卡片。

### 6.2 物品页

**当前重点：** 数据量大，需要强化搜索、筛选和卡片扫描。

- 搜索框优先级高于重新扫描；
- 数量 Stepper 与搜索保持同一工具栏，但不要与搜索框争夺宽度；
- 当前分类按钮使用 Accent；
- 资产总数、模组数、搜索结果数放在搜索栏下方；
- 卡片名称和来源标签分层；
- 空搜索结果必须显示“清空搜索”或明确返回方式。

### 6.3 车辆页

车辆卡片的图标来源可能是官方图标或模型缩略图。建议：

- 加载中的缩略图显示低干扰占位状态；
- 缺失图标时使用统一的“无预览”视觉，而不是让卡片空白；
- 名称过长时优先保留可识别前缀；
- 生成数量使用和物品页相同的 Stepper 结构；
- `模组`、`Vanilla Built-in` 等来源统一为短标签。

### 6.4 收藏页

- “物品收藏 / 车辆收藏”继续使用分段切换；
- 当前数量只统计当前已加载、可操作的收藏对象；
- 收藏空状态和列表状态使用同一块内容区域，避免出现“0/1”一类歧义；
- 收藏卡片沿用物品/车辆卡片，不要另造一套卡片外观；
- 取消收藏后保留短暂 Success 状态反馈。

### 6.5 传送页

- 保存当前位置区域使用明确的输入提示；
- 地图和坐标使用 Muted；
- 已保存传送点使用低突兀的 SurfaceInset、1px 边界和左右/上下内边距，
  避免文字贴边或列表框架过于突兀；
- 当前地图可传送按钮为 Primary/Accent；
- 其他地图按钮 Disabled + Warning 说明；
- 删除按钮只保留红色小按钮，不与传送按钮同宽；
- 传送点名称、地图、坐标应有固定的两行结构。

### 6.6 其他页

建议拆成三个明显区块：

1. **时间：** 当前时间、Slider、精确输入、白天/夜晚；
2. **世界事件：** 冻结时间、满月、空投、天气；
3. **扫描信息：** 物品/车辆数量、重新扫描和说明。

不要让“重新扫描模组资产”与天气操作拥有相同的视觉权重；它应属于
扫描信息区的 Secondary 操作。

### 6.7 状态栏

- 状态栏保留底部固定位置和左侧语义色条；
- 使用独立的 SurfaceInset 和 1px 边界，避免与主面板背景融合；
- 使用固定高度，不随页面内容或状态文本换行而伸缩；
- 文本与边界保持明确内边距，状态类型仍由前缀、文字和色条共同表达。

## 7. 响应式、Scale 与输入规范

### 7.1 基准分辨率

当前 Canvas 使用 1920×1080 作为参考分辨率，并使用
`ScaleWithScreenSize`。该选择继续保留。

### 7.2 UI Scale

保留现有配置范围 `0.75–1.5`，最终缩放继续取：

```text
实际 Scale = min(用户配置 Scale, 当前屏幕安全 Scale)
```

重点不是让所有分辨率都保持完全相同的内容密度，而是保证：

- Header 不被裁切；
- Tab 仍可点击；
- 主要内容不覆盖状态栏；
- 关闭、删除、确认等关键按钮不会离开屏幕；
- 鼠标位置与视觉控件位置一致。

已有 2560×1440 六页截图可作为高分辨率视觉基线。若后续继续扩大
低分辨率验收，应优先检查 1280×720 和英文模式。

### 7.3 输入与焦点

- 打开菜单时保留现有鼠标显示和游戏输入隔离；
- 关闭菜单后恢复游戏输入；
- 输入框获得焦点时不要让游戏视角继续跟随鼠标；
- 关闭按钮、确认框取消按钮和当前 Tab 应具备明确焦点反馈；
- 不用颜色作为唯一焦点指示；
- 未来如加入键盘导航，焦点顺序应为 Header → Tab → 工具栏 → 内容 → 状态。

## 8. 推荐落地顺序

### Phase A：视觉基础统一

**目标：** 不改页面结构，先建立可复用的视觉语义。

- 扩展 `CheatMenuStyle`：补充 `SurfaceRaised`、`Success`、`Warning` 等语义色；
- 统一 Button 的 Normal/Highlighted/Pressed/Disabled；
- 统一 Input 的 Placeholder、Focus、Disabled；
- 统一 Tab、Toggle、Favorite、Pagination 的状态色；
- 将 Status Bar 从单一黑条提升为类型化反馈。

**验收：**

- 六个页面无明显错位；
- 中英文文本不出现严重截断；
- 颜色变化不影响功能；
- 无新增第三方依赖。

### Phase B：层级与密度优化

**目标：** 不更换 Overlay 架构，调整页面内的区块节奏。

- 角色页加入状态 Summary 与操作组层级；
- 其他页拆分时间、世界事件、扫描信息；
- 物品/车辆卡片统一名称、元信息和来源标签；
- 传送列表强化地图差异；
- 空状态补充下一步操作提示。

**验收：**

- 用户能够在不逐字阅读的情况下找到主要动作；
- 物品/车辆页能快速区分搜索、分类、数量和分页；
- Danger 操作不会与普通操作混淆。

### Phase C：真实运行与可访问性回归

**目标：** 用真实游戏证据验证静态设计没有破坏交互。

- 中英文；
- 0.75 / 1.0 / 1.5 三档 Scale；
- 角色、物品、车辆、收藏、传送、其他六页；
- 搜索、分页、收藏、传送确认、Toggle、Slider；
- Hover、Pressed、Disabled、Focus；
- 菜单打开/关闭、HUD 共存、输入恢复；
- 真实日志中不得出现 UI rebuild loop 或新增异常。

**当前状态（2026-08-16）：** 六页真实运行截图已完成本轮视觉子集验收，视觉边界、
尺寸、纹理和图标对齐问题已闭环。中英文、三档 Scale、输入捕获/恢复、实际控件操作、
日志与性能回归仍需各自的运行证据，不因截图验收而自动标记为完成。

## 10. 明确不做的事项

本方案不包含以下改动：

- 不更换为 Dear ImGui、UImGui、UI Toolkit 或 WebView；
- 不引入第三方 UI DLL；
- 不建立独立 Unity UI 工程；
- 不引入 AssetBundle、Prefab 或 ScriptableObject Theme；
- 不重写 `CheatActions`、`AssetCatalog`、`FavoriteStore`、`TeleportStore`；
- 不修改单人模式守卫、BattlEye 边界、多人限制或 Harmony 逻辑；
- 不为了视觉统一删除可回退的 Legacy UI 文件；
- 不把“编译通过”当作真实视觉验收；
- 不以大规模动画、发光、渐变或背景特效替代信息层级。

## 11. 最终设计结论

当前插件不需要“大换血”。最稳妥的优化路线是：

1. 保持 `Screen Space Overlay + 动态 uGUI`；
2. 继续使用 `CheatMenuStyle` 作为轻量视觉 Token 入口；
3. 用语义色和状态设计解决“按钮都一样”的问题；
4. 用区块分组解决角色页、其他页的按钮墙；
5. 用卡片信息分层解决物品/车辆页的扫描负担；
6. 用类型化 Status Bar 和更明确的空状态/确认框提升反馈；
7. 已用真实单人世界中的六页截图完成本轮视觉项反向验收；双语、三档 Scale、实际交互和
   日志回归继续按证据边界单独验收。

最终目标不是让插件看起来像一个独立桌面应用，而是让它在 Unturned 场景中
成为一套**低干扰、可快速扫描、状态明确、不会误操作的游戏内工具面板**。
