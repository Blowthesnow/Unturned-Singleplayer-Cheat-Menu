# 自动拾取完整落地与验收账本

> 更新日期：2026-08-25  
> 目标：在真正的单人世界中提供默认不限制物品的自动拾取，用共享背包物品卡片维护可选白名单和始终生效的黑名单，并阻止满包请求与玩家主动丢弃物品回捡。

## 一、最终行为

- 自动拾取只在 `SingleplayerGuard.IsReady` 成立时运行，不移动玩家，不修改原生距离常量。
- 扫描和发送拾取请求共同使用一个“拾取距离”值，范围固定为 1–1000 米。
- 设置页只显示一个时间控制同款滑条，不再显示“扫描半径”和“请求距离”。
- 白名单默认关闭；开启后只拾取 `Allow + AssetId` 白名单物品，添加首个白名单物品会自动开启白名单。
- 黑名单始终生效并最终否决；同一物品同时位于白名单和黑名单时不拾取。白名单关闭且黑名单为空时默认允许所有物品。
- 过滤模型只接受启用的 `Allow/Deny + AssetId` 规则；关键词、GUID、名称、分类、类型、重复规则、禁用规则和非法 ID 在加载时跳过。
- 规则文件仍使用原子写入；旧 `BlacklistOnly + Enabled=true` 文件迁移后保持白名单关闭，不会因旧字段含义误开启白名单。
- 拾取请求继续使用游戏原生 `ItemManager.takeItem` 路径，并保留扫描频率、每轮预算、10 次/秒请求节流、失败退避和诊断。
- 每次原生请求前使用 `PlayerInventory.tryFindSpace(...)` 检查随身背包能否容纳物品；没有空间时不发送请求，并对该掉落暂停 5 秒。
- `PlayerInventory.onDropItemRequested` 与 `ItemManager.onItemDropAdded/onItemDropRemoved` 将玩家主动丢弃请求和实际掉落模型精确配对；该掉落实体移除前不会被自动拾取。

实际 `LogOutput.log` 中的“失败 422 次”不是 HTTP 422：其中 421 次为同一批 `id=81` 掉落实例在背包不能接纳时被反复请求并记为 `RejectedByCapacity`，另 1 次为掉落消失但背包数量未增加。请求前容量门禁消除了主因。

官方稳定文档确认 `ItemAsset.ID` 为 `uint16`。运行时背包枚举使用当前游戏程序集中的 `Player.LocalPlayer.inventory.items`、`Items.getItemCount()`、`Items.getItem()` 和 `ItemJar.GetAsset()`。

## 二、界面落地

### 设置与主分页

- 工具页保留“自动拾取”子页。
- 第 1 页显示开关、暂停条件、统一拾取距离、扫描频率、每轮请求预算、诊断、白名单开关和两类名单入口。
- 第 2 页起依次显示白名单和黑名单卡片，每页 10 个；两类名单至少各保留一个管理页，页数随物品数量动态增加。
- 鼠标滚轮在页面内容区域连续翻页，不显示“上一页”或“下一页”按钮。
- 右侧按实际总页数竖向显示 `●`，整体居中；当前页点使用高亮色，页数增加时自动缩小以控制高度。
- 自动拾取页固定为紧凑高度，卡片分页避免窗口随规则数量增长。

### 添加白名单/黑名单

- 点击“添加白名单”或“添加黑名单”打开同一个参数化背包映射窗口。
- 只枚举当前玩家随身背包页，不包含外部储物容器。
- 使用 `HashSet<ushort>` 按物品 ID 自动去重；同 ID 的多份物品只显示一张卡片。
- 卡片沿用物品页图标、名称和元信息布局。
- 点击未加入的卡片立即添加对应 ID 名单；已加入的卡片显示名单状态且不会重复添加。添加白名单物品会自动启用白名单。
- 背包物品较多时通过鼠标滚轮分页，不显示翻页按钮。
- 支持按名称、ID、GUID 和来源搜索。

### 管理白名单/黑名单

- 白名单和黑名单复用同一套参数化卡片管理页，不提供手工文本输入或规则字段控件。
- 点击名单卡片立即取消对应物品 ID；添加成功后立即重建并切换到相应管理页，不再显示旧快照。
- 支持搜索；搜索结果仍并入主页面的滚轮分页与右侧页点。
- 空白名单说明开启后只拾取白名单物品；空黑名单明确说明默认不限制物品。

### 悬停详情

- 背包选择卡片、白名单管理卡片和黑名单管理卡片均调用 `AssetHoverDetailsBuilder.BuildItem(...)`。
- 卡片使用 `delayTooltip: true`，保持物品页同款延迟悬停。
- 悬停内容继续包含物品基础信息、描述、弹药/兼容信息等现有完整详情，不以简化提示替代。

## 三、配置与兼容迁移

```ini
[AutoPickup]
Enabled=false
Range=40
FrequencyHz=10
RequestsPerTick=4
FilterMode=BlacklistOnly
RulesPath=AutoPickup.rules.json
PauseWhenMenuOpen=true
PauseWhenDead=true
Diagnostics=Failures
```

- `Range` 是唯一运行时距离配置。
- 旧 `ScanRadius` 和 `RequestRange` 只作为迁移兼容键保留；首次迁移取两者较小值，以维持旧版两个距离门禁叠加后的有效范围。
- 调整新滑条时三个键会同步，避免旧版本回退后读到互相冲突的距离。
- `AutoPickupSettings.ScanRadius` 和 `RequestRange` 仅保留为转发到 `Range` 的代码兼容别名。
- `FilterMode` 保存为 `BlacklistOnly` 或 `WhitelistThenBlacklist`；白名单开关和规则文档共同决定当前模式，旧 `WhitelistOnly` 读取时规范化为后者。

## 六、游戏内最终验收步骤

1. 进入真正的单人地图，打开工具页的自动拾取。
2. 确认只看到一个“拾取距离”滑条，端点可设为 1 和 1000 米。
3. 白名单关闭且黑名单为空时，确认普通地面物品会被拾取且玩家位置没有变化。
4. 打开“添加白名单”，确认同 ID 多份物品只出现一张卡片；悬停详情完整，点击后自动启用白名单且只拾取白名单物品。
5. 将同一物品加入黑名单，确认黑名单覆盖白名单；在两类管理页点击卡片可立即取消且页面马上刷新。
6. 制造足够多的白/黑名单页，确认鼠标滚轮翻页、无翻页按钮、右侧点数正确、当前点高亮且整列垂直居中。
7. 从原生背包界面主动丢弃物品，确认该掉落实体不会被自动捡回；附近同 ID 的其他普通掉落仍可按规则拾取。
8. 填满随身背包，确认显示容量暂停且不再累计原生请求失败；腾出空间后最多等待 5 秒恢复。
9. 分别验证菜单打开暂停、死亡暂停、超出拾取距离和重新进入地图后的状态。
