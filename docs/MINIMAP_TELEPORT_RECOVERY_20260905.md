# 小地图传送恢复 v8

## 用户边界

**不以图片越界本身切换实时背景。** 普通行走到地图边缘仍按原有原生地图规则显示，包括保留部分覆盖裁剪。`MinimapRenderPolicy.cs`（含 native-edge 与道路相机深度策略）与修改前逐文本一致。

## 实现

- 绑定当前本地 Player 的原生 `onPlayerTeleported` 通知；本机签名为 `PlayerTeleported(Player, Vector3)`。不 Harmony patch、不发起传送。换玩家、场景退出和 Dispose 时解绑。
- 回调只记录通知，扫描/渲染在后续正常 Update 处理。
- 收到通知后，立即重置背景迟滞和扫描/投影/遮挡/渲染计时，失效场景对象缓存，丢弃可能仍属于出发点的共享物品快照。
- **只有原生传送通知 + 目的地无原生图片交集 + AutoNativeFirst** 才锁定该目的地的实时恢复。持续停留该目的地时保留，玩家实际回到原生坐标范围内后解除；仅缩放图片产生交集不解除。
- 64 米级位置突变是补充的缓存失效信号，绝不据此启用实时目的地锁定。
- 实时恢复仍进行室内遮挡判断，能够进入高度切片；没有原生底图时不再跳过遮挡状态机。
- 手动 NativeMapOnly / RealtimeSurface / RealtimeHeightSlice / Disabled 仍保持用户选择，不改配置。

## 验证范围

- MinimapSmoke 覆盖：普通越界不切、位置突变不切、原生传送无图恢复、目的地状态保持、返回有图区域、传送至部分覆盖边缘、会话重置、无图室内进入/退出高度切片，以及事件订阅/解绑源码约束。
- 编译和静态/数学测试不能证明某个地图模组真的调用了原生传送通知。若模组直接改 Transform 而不发通知，该路径只刷新缓存，不擅自改背景。
- 若插件首次绑定前就已身处副本，或场景重置后没有新的传送通知，不会凭当前位置越界擅自建立实时恢复标记。
- 若选择了“仅原版地图”或关闭已加载建筑，仍可能没有副本地面图形；本轮不会暗改这些选择。
- 山水、树冠、已撤回光影和道路相机几何均保持既有行为。

主输出仍为 `D:\Unturned BepInEx\artifacts\UnturnedSingleplayerCheatMenu.dll`。未自动替换游戏目录。实机需检查进入副本时的 `relocation-refresh-v8: source=teleport-event` 日志、背景是否恢复，以及返程后普通地图边缘是否仍保持原版底图。
